# Frontend output limits

The second 50-record run on 0.27.13rc2 failed on records 26 and 28: Final reached the 1,200-token budget twice, and one analysis point returned six proofs against a five-proof schema limit twice.

0.27.14rc1 removes application-level Preview/Final token budgets, generated-byte caps, fixed prose-length instructions, Final text-length validation and proof-count limits. Valid original quotations are retained in full instead of being shortened to 120 characters or dropping evidence after entry 14. Frontend cache policy changes so prior results cannot stand in for the new implementation.

Omitting `max_tokens` delegates to the model provider's default; this does not make the model physically unlimited. Provider `finish_reason=length` remains an incomplete result with one bounded retry. GLM-5.2 documents a default 65,536-token output budget: https://docs.bigmodel.cn/cn/guide/start/concept-param

Formal scoring requests keep their existing settings. Access controls, original-source checking, semantic observation, version checks and writeback protections remain in place. Shared transport callers still enforce their explicit byte budgets.

Validation: 415 Python tests, 44 JavaScript interaction tests, three Chrome scenarios (long text, recovery, superseded record), Ruff, Compose validation and package build. Release guard backs up database/configuration/image, checks the previous deployed commit and changes only the TAORAN container. Retest scope is the original second-batch records 26 and 28 only; original failed results remain preserved.
